# EGX Analytics Mobile — Roadmap and Shared Contracts

This is the spine for the five implementation plans that port the EGX Analytics
web app (`../egx-api-fe`, Next.js 14) to a React Native app in this repo
(`egx-api-mobile`, Expo SDK 57). **Every plan's Global Constraints include this
file.** Read it before executing any task in any plan.

| # | Plan | Depends on | Ends with |
|---|---|---|---|
| 1 | [Foundation](2026-10-10-01-foundation.md) — shared code, theme, auth, navigation shell, UI kit, data providers | — | Sign in on a phone, four empty tabs, every route reachable |
| 2 | [Charts](2026-10-10-02-charts.md) — SVG chart kit + every chart component | 1 | A `/dev/charts` gallery screen rendering every chart from fixtures |
| 3 | [Market screens](2026-10-10-03-market-screens.md) — Dashboard, Stock detail, Compare, News, Dividends calendar | 1, 2 | Browse the market end-to-end on a phone |
| 4 | [Portfolio](2026-10-10-04-portfolio.md) — Portfolio screen, holdings, buy/sell/dividend forms, realized, advice, risk | 1, 2 | Manage a real portfolio on a phone |
| 5 | [Learn, admin, release](2026-10-10-05-learn-admin-release.md) — Learn path, Calibration, Admin, icons, EAS build | 1, 2 (3/4 for deep links only) | An installable build |

Plans 3 and 4 touch disjoint files and may be executed in parallel once 1 and 2
are merged.

## What the web app is (read its guide)

`../egx-api-fe/CLAUDE.md` is the authoritative product guide — business rules,
colour rules, why every number is computed the way it is. **The mobile port
changes the rendering, never the rules.** Before porting a screen, read that
screen's section of the guide and the web component source. In particular the
following rules carry over verbatim and are easy to break in a rewrite:

- `gain` green / `loss` red mean a real direction in the data, never decoration
  (risk bands, dividends, news, oversold breadth, low-confidence zones are neutral).
- Score labels are CONDITION words (Very Weak … Very Strong) via `scoreBand()` /
  `SCORE_BAND_LABEL` — never Buy/Sell.
- One card per STOCK in the portfolio (`groupHoldings`), FIFO sale preview
  (`planSale`), annualized return never aggregated.
- Learn anchors are a public contract (backend `learn_concept` ids).
- Money inputs accept 3 decimals (EGX quotes to 3dp); share counts are integers.
- Every composite score is educational — the disclaimer is shown where the web shows it.

    denied route falls back to the first available screen.
  - Router tests use `renderRouter` from `expo-router/testing-library`;
    **test files must NOT live inside `src/app/`**.
  - NativeWind **4.2.7** (Tailwind CSS 3) supports SDK 57 with Reanimated 4 + `react-native-worklets`.
- Everything in Plans 1–4 must run in **Expo Go** (no custom native modules).
  `react-native-svg`, `expo-secure-store`, Reanimated, gesture-handler and
  `@expo-google-fonts/*` are all in Expo Go.
- Long-running commands (Metro, `expo start`, full test runs > 2 min, EAS builds)
  run in tmux per the user's global rule:
  `tmux new -d -s egx-mobile-<task> "<cmd> 2>&1 | tee ~/logs/egx-mobile-<task>.log"`.

## Import aliases

`tsconfig.json` maps `@/*` → `./src/*` (Expo resolves tsconfig paths in Metro;
Jest maps it with `moduleNameMapper`). Always import across folders with the
alias: `@/shared/api`, `@/ui`, `@/charts`, `@/providers/watchlist`,
`@/features/market/StockCard`. Relative imports only within one folder.

## Shared code — one source of truth in the web repo

`egx-api-fe/src/app/lib/*.ts` holds the API client, response types, constants,
position maths and colour tokens. The mobile app must not fork them.

- `npm run sync:shared` copies the files listed in `scripts/sync-shared.mjs`
  (`SHARED_FILES`) from `../egx-api-fe/src/app/lib/` into `src/shared/`, adding a
  `// GENERATED` header.
- `npm run check:shared` fails if any copy differs from its source (ignoring
  the header) or the sibling repo is missing. Set `SKIP_SHARED_CHECK=1` only on a
  machine without the web repo (e.g. EAS cloud builds).
- **To change shared code: edit it in `egx-api-fe`, commit there, run
  `npm run sync:shared` here, commit here.** Never edit `src/shared/`.
- Shared files must stay platform-neutral: no `window`, `document`,
  `localStorage`, `next/*`, React DOM, or component imports. Plan 1 Task 1
  makes `api.ts` meet this rule.

Shared modules after Plan 1: `api`, `apiConfig`, `auth`, `types`, `constants`,
`positions`, `riskBands`, `theme`.

## Route map (web → mobile) and link helpers

| Web | Mobile route | Helper (`@/lib/links`) |
|---|---|---|
| `/` | `/(tabs)` index | `routes.dashboard` |
| `/portfolio` | `/(tabs)/portfolio` | `routes.portfolio` |
| `/learn`, `/learn#<id>` | `/(tabs)/learn?concept=<id>` | `learnHref(conceptId?)` |
| `/news` | `/(tabs)/news` | `routes.news` |
| `/stock/[symbol]` | `/stock/[symbol]` | `stockHref(symbol)` |
| `/compare` | `/compare` | `routes.compare` |
| `/dividends` | `/dividends` | `routes.dividends` |
| `/calibration` | `/calibration` | `routes.calibration` |
| `/admin` | `/admin` (admin only) | `routes.admin` |
| `/login` | `/login` | — |

A web `<a href="/learn#rsi">` becomes `<Link href={learnHref("rsi")}>` or
`router.push(learnHref("rsi"))`. The Learn screen (Plan 5) reads the `concept`
search param and scrolls to that concept exactly as the web hash router does.

## Styling

- NativeWind 4 `className` strings, mirroring the web's Tailwind classes where they
  exist in React Native. The phone is the only form factor: drop every `md:`/`lg:`
  variant and keep the mobile (unprefixed) branch of the web layout.
- Colours come from `@/shared/theme` (`COLORS`), registered in
  `tailwind.config.js` under the same names as the web (`charcoal-dark`,
  `charcoal`, `gain`, `loss`, `accent`). Charts and anything needing a hex in JS
  import `COLORS` directly — never retype a hex.
- **Fonts:** React Native cannot synthesise weights for custom fonts, so weight
  is a family. Use these classes, never `font-semibold`/`font-bold` alone:
  `font-sans` (Outfit 400), `font-sans-medium` (500), `font-sans-semibold` (600),
  `font-sans-bold` (700), `font-mono` (JetBrains Mono 400),
  `font-mono-semibold` (600). The web's `font-mono text-sm font-semibold` becomes
  `font-mono-semibold text-sm`.
- No hover states. Touch targets are **at least 44pt** (`min-h-[44px]`).
- Safe areas come from `react-native-safe-area-context` via the `Screen`
  primitive, never hardcoded insets.
- Web-only CSS with no RN equivalent (`backdrop-blur`, CSS grid, `position: sticky`,
  keyframe animations) is translated per component and the translation is
  noted in that task.

## Providers contract (built in Plan 1)

Same shapes as the web, so ported code reads identically:

- `useAuth()` from `@/auth/AuthProvider` → `{ user: AuthUser|null; isAuthenticated; isAdmin; isLoading; error: string|null; login(u, p): Promise<void>; logout(): Promise<void> }`
- `useScoreWeights()` from `@/providers/scoreWeights` → identical to web `ScoreWeightsCtx` (`weights, draft, presets, loading, saving, error, version, setDraft, updateDraftField, resetDraft, applyPreset, save`) and `normalizeWeights` export.
- `useTickers()` from `@/providers/tickers` → `{ tickers: Ticker[]; loading: boolean }`.
- `useWatchlist()` from `@/providers/watchlist` → `{ symbols; loading; add(sym); remove(sym); has(sym) }` (no localStorage migration — mobile never had one).

name and the same props interface** as the web component, so screen ports in

from the parent's layout (`onLayout`), never `Dimensions` at module scope.

## Testing contract

- Jest with `jest-expo` preset + `@testing-library/react-native` (v14+).
- `npm test` runs everything; `npm run verify` = `check:shared` + `tsc --noEmit` + `expo lint` + `jest`.
  **Every task ends with `npm run verify` green before its commit.**
- Network is mocked with `mockFetch` from `@/test-utils/fetch` (Plan 1), never by
  hitting the real API. Screens are rendered with `renderWithProviders` from
  `@/test-utils/render` (Plan 1) which mounts the real providers over mocked fetch.
  Exact signatures (Plan 1 Tasks 4, 6, 8):
  - `mockFetch(method, path: string | RegExp, body, status = 200)` — appends a
    route; a string path matches the pathname after `https://api.test/api`
    exactly (query ignored), a RegExp is tested against the full URL; **the most
    recently registered match wins**; an unmatched request throws.
    `mockFetchHandler(method, path, (url, init) => ({ status, body }))` for request-dependent replies,
    `mockFetchNetworkError(method, path)`, `prependMockFetch(...)` (a fallback
    any `mockFetch` overrides), `fetchCalls()` → `{ method, url, headers, body }[]`.
    `global.fetch` is a fresh `jest.fn()` before every test (`jest.setup.ts`).
  - `await renderWithProviders(ui, { user?: AuthUser | null })` — async; signed in
    as `{ id: "u1", username: "tester", role: "user" }` by default; uses RNTL's
    `wrapper` option so `rerender` keeps `TestSafeArea` + `AuthProvider` + `AppProviders`.
  - `TestSafeArea` from `@/test-utils/safeArea` — wrap anything that renders `Sheet`/`Screen` outside `renderWithProviders`.
- Plan 2 Task 1 wraps the root layout in `GestureHandlerRootView`.
- Test behaviour a user would notice (what renders, what is called, what
  happens on error), not implementation details.
- Manual device check: `npx expo start` in tmux, open in Expo Go on the phone
  (same LAN, or `--tunnel`). Each plan's last task lists what to check by hand.
